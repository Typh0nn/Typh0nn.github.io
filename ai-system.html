Built continuously since April 2026 · solo technical founder

A multi-agent AI system built as an operating system, not a wrapper.

It started as an experiment in asynchronous agent debate. It is now a runtime that carries business processes end to end: an Athenian debate layer for deciding what is worth doing, a Roman hierarchy for getting it done, a compiled knowledge base that keeps context from drifting, and a portfolio of live projects sharing one orchestration bus. My role in it is deliberately narrow — strategic orchestrator, and the human on the high-stakes approvals.

01

The problem it exists to solve

Stated plainly, including the part that is uncomfortable.

Without it

Plans that never survive contact with execution

An idea gets researched, scoped and written up beautifully — and then stalls, because every step after the plan needs a person to sit down and do it. The bottleneck is never the thinking. It is the hundred small executions between a plan and a result.

The generic AI answer makes this worse, not better: a swarm of agents left to run free produces more artefacts and less finished work, burns money unpredictably, and leaves you unable to say which agent wrote which record.

With it

Loops that close without me in the middle

The system is judged on one test: does the loop close? A blueprint goes in; research, drafts, assets, publication and measurement come out; I am consulted where judgement or liability genuinely requires a human, and nowhere else.

The controls are the product. Spend is bounded per call. Output is graded before it ships. State has exactly one writer. Anything irreversible or outward-facing stops at a gate and waits for me.

02

From experiment to runtime

Continuity is the point. The compounding only works if you do not restart.

April 2026

An experiment in agent debate

The starting question was narrow: can several agents argue asynchronously and reach a better answer than one agent asked politely? That experiment became the meta-debate layer and set the direction for everything after it.

Through spring

Structure before capability

Rather than adding agents, the effort went into the parts that make agents survivable: an execution engine, a supervisor, a typed knowledge base, documentation treated as operational memory rather than as prose.

July 2026 →

A stable runtime carrying real work

The system now runs complex processes without supervision between checkpoints, and spawns new business lines onto the same bus. It is privately operated, not a commercial product — the distinction matters and I keep it.

Why the continuity matters

Sustained development is what kept this out of the AI-wrapper trap — a thin layer over a model that has to be rebuilt every time the model changes. What accumulates instead is structural knowledge: compiled operating history, standards the system enforces on itself, and conventions that new agents inherit rather than relearn. That is not available to something assembled for a single demo.

08

Six positions I would defend in a review

These are the decisions that cost the most to get wrong, so they were made explicitly.

01

Workflow-first, explicitly anti-AutoGPT

Deterministic workflow wherever the steps are known; a model only where judgement is genuinely required. Free-running agent loops are a liability, not an architecture. This was a correction to my own earlier design, not a starting assumption.

02

Single-writer state

Exactly one component owns writes to a given record. It removes an entire class of race conditions and makes provenance answerable. Straight out of master data management, where "who is allowed to change this field" is the whole discipline.

03

Cost is a design constraint

Model choice is configuration per role, never hard-coded, and spend is metered per call against an enforced budget. A run that exceeds its budget stops rather than quietly becoming expensive.

04

Buy the commodity, build the core

The orchestration bus is self-hosted n8n because a proven engine beats a bespoke one, and my time is better spent on the parts nobody sells. Custom code only where the actual intellectual property lives.

05

Minimum viable context

Agents are served the smallest relevant slice of data rather than everything available. It cuts token spend sharply and, less obviously, improves precision — a model given less irrelevant material makes fewer irrelevant decisions.

06

Honest about what is not done

It runs privately and is in active development. Some loops close cleanly; others still hand work back to me, and those are the open items. I would rather show the seam than claim a finished product.

09

What it has actually solved

Concrete outcomes, separated from intentions.

Unpredictable cost
Spend is metered per model call against an enforced budget, with model selection as per-role configuration. Local and cheap models carry the routine load; the expensive ones are reserved for work that demonstrably needs them.
Hallucination by consensus
The rotating-role debate means no agent ever argues only its own side, and agreement has to survive a designated critic. Diversity of perspective is structural rather than hoped for.
Silent bad output
An LLM-as-judge evaluation layer grades output before it moves downstream, and the Tribune veto blocks anything breaching brand safety or budget outright.
Runaway agents
Replacing open-ended loops with explicit state machines made runs inspectable: named states, legal transitions, and retry and timeout handling rather than an indefinite retry. A supervisor daemon watches for drift and escalates.
Context drift
A compiled, deduplicated knowledge base under a schema means the system does not forget standards it already agreed to, and a new agent can be brought into a project in seconds rather than hours.
Conflicting writes
A single-writer rule over shared state removed the class of bugs where two agents update the same record and the last one silently wins.
Unverifiable AI output
Generated media carries C2PA provenance signatures, so the question "was this AI-generated" has a checkable answer rather than a promise.
Still open
End-to-end autonomy on the harder business loops, and evaluation coverage broad enough that I trust the judge without spot-checking. Both are in progress, and I would not claim otherwise.
10

Why this belongs on a master data CV

The connection is not decorative.

Same discipline

Governance is governance, whatever is writing the record

Deciding who may write a field, validating input before it lands, keeping one version of the truth, enforcing a schema, and putting a human on the decisions that carry liability — that is master data management. It is also, line for line, what makes an agent system safe to run.

The reason I reached for single-writer state, a typed knowledge base and budget enforcement early is that I have spent eight years cleaning up what happens when nobody did.

What it means for an employer

I know where these tools break

I have run the cost, quality and reliability problems in something I own, which is a different kind of knowledge from having read about them. When a stakeholder asks whether an LLM can take over a reporting process, I can answer with the failure modes attached.

And when the answer is that a deterministic pipeline would do it better and cheaper, I will say so.

The short version

I have spent eight years making large organisations agree on their data, and the last several months building a system that has to live by those same rules to work at all. One is on my CV; the other is the reason I can talk about AI in a reporting function without either overpromising or dismissing it.
